# 実装フロー

## 原則

実装タスクは Claude 単独で進めず、規模に応じて **`/solo-with-verifier`** または **`/orchestra-of-agents`** スキルを必ず起動する。Claude が単独で TDD サイクルを回す「サボり」は禁止。

## 規模別の使い分け

| 規模 | スキル | 役割 |
|---|---|---|
| 1〜3 ファイル / 1〜3 タスクの小〜中規模 | `/solo-with-verifier` | Implementer + Verifier の 2 エージェントを最大 3 反復 |
| 4 タスクのグレーゾーン | 下記「4 タスクの判断」参照 | デフォルトは orchestra に倒す |
| 5 タスク以上 / 複数モジュール横断 | `/orchestra-of-agents` | Wave 方式の並列実装 + クロスレビュー + 横断レビュー |
| typo 1 行 / 設定 1 行 | 単独 OK | スキル起動のオーバーヘッドが上回るケースのみ。「単独で進める理由」を明示すること |

## 4 タスクの判断

- 互いに**依存があり直列的** → `/solo-with-verifier`（反復で吸収）。選ぶ場合は理由を明示
- **独立性が高く並列化が活きる** → `/orchestra-of-agents`
- **横断レビューが要る**（複数モジュール、共通基盤に触る） → `/orchestra-of-agents`
- 迷ったら `/orchestra-of-agents` に倒す（安全側）

## 運用ルール

- 「修正して」「実装して」「追加して」「直して」「リファクタして」等の実装系依頼を受けたら、**まず規模を見積もってどちらのスキルを使うかを宣言してから着手する**
- 単独実装に倒すのは「typo 1 行のため」のような明示的な理由がある場合のみ。「速いから」は理由にならない
- 規模見積りが難しい場合は、ユーザーに方針を確認するか `/solo-with-verifier` をデフォルトに倒す

## Why（このルールが必要な理由）

- Claude 単独 TDD では Verifier の独立視点（仕様適合・テスト網羅性・rules 遵守・検証コマンド）が入らず品質担保が弱い
- 特に `/orchestra-of-agents` を「サボって使わない」傾向がある。中〜大規模実装で単独進行するとレビュー観点の取りこぼし・テスト網羅性の不足が起きやすい
- 実際に 8 ファイル変更・9 タスク規模の修正（本来 `/orchestra-of-agents` の射程）を Claude が単独で完結させ、レビュー観点の取りこぼしをユーザーから指摘された事例がある
