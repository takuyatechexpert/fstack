# 起動モードの詳細（Codex 委譲・複数 PR）

このファイルは、引数先頭が `codex` のとき、または複数 PR が指定されたときに親が Read する。

## Codex 委譲モードの手順

`review-codex` は別途導入が必要。未導入なら、その旨を伝え `codex` なしの標準モードでの起動を案内して終了する。

1. ARGUMENTS の先頭 `codex` を除去し、残りを依頼本文として抽出（例: `/review-pr codex #1234 のレビュー` → `#1234 のレビュー`）
2. 「Codex にレビューを委譲します」と通知し（モデル名は review-codex 側の定義に従い、こちらでは明示しない）、`Skill` ツールで `review-codex` を呼んで `args` に本文をそのまま渡す
3. review-codex の出力を**再加工せず**そのまま提示する（本スキルの Phase 2 以降は実行しない）

worktree は作らない（差分は review-codex 側の `gh pr diff`）。マルチ視点・偽陽性チェック・影響範囲チェックは入らないため、本格レビューが必要なら `codex` を付けずに起動する旨を案内する。

## 複数 PR 指定時

- **標準モード**: PR ごとに個別サブエージェントを**同一ターン内で並列 spawn** し、各自に「review-pr の標準ワークフロー（Phase 1〜7）を単独で実行せよ」と指示する。PR 内の worker + verifier 展開は単一 PR 時のみ（PR 数 ×（worker 最大 8 + verifier）のエージェント爆発と並列枠枯渇の回避）。**参照ファイルは絶対パスのみ渡し、本人に Read させる**（要約渡しは項目欠落の原因）
- **Codex 委譲モード**: review-codex を **PR ごとに直列呼び出し**（`codex exec` は 10 分タイムアウト + I/O 集中でローカル並列メリットが薄く、レートリミット直撃リスクあり）。「PR #X 依頼中…（残 N 件）」と進捗通知し、1 件失敗時は継続可否を確認
