# エージェント デザインパターン集

## パターン一覧

| パターン | 用途 | モデル | maxTurns目安 |
|---------|------|--------|-------------|
| A: 読み取り専用アナリスト | 設計分析、影響範囲調査、コードレビュー | sonnet | 15 |
| B: 実装エージェント | 機能実装、バグ修正、リファクタリング | sonnet | 30 |
| C: オーケストレーター | 大規模タスクの分割・並列実行・結果統合 | opus | 20 |
| D: バックグラウンドワーカー | CI風チェック、静的解析、依存関係確認 | haiku | 10 |
| E: メモリ付き学習エージェント | プロジェクト固有の知識蓄積・文脈判断 | sonnet | 20 |

---

## パターン A: 読み取り専用アナリスト

コードを読み取って分析するだけで、変更は一切行わない。

```yaml
---
name: {agent-name}
description: "{目的を具体的に記述}。コードの変更は一切行わない。"
tools: Read, Grep, Glob, Bash
disallowedTools: Write, Edit, NotebookEdit, Agent
model: sonnet
maxTurns: 15
---
```

**本文テンプレート:**

```markdown
あなたは{専門領域}の専門家です。コードを読み取って分析するだけで、変更は一切行いません。

## 責務

- {責務1}
- {責務2}
- {責務3}

## 分析の観点

### {観点1}
- ...

### {観点2}
- ...

## 出力フォーマット

{マークダウンテーブルやリスト等の構造化フォーマット}

## 制約

- コードの変更（Write/Edit）は絶対に行わない
- 設計の分析と提案のみ行う
- 判断に迷う場合はトレードオフを明示し、選択をユーザーに委ねる
- Bash は `git log`, `git diff`, `git show`, `ls`, `wc` 等の読み取り系コマンドのみ使用する
```

**実例:** `architect` エージェント（設計分析・アーキテクチャ評価）

## パターン B: 実装エージェント

指定されたタスクのコード実装を行う。

```yaml
---
name: {agent-name}
description: "{対象領域}のコード実装を行うエージェント。{トリガー条件}。"
tools: Read, Write, Edit, Glob, Grep, Bash
model: sonnet
maxTurns: 30
isolation: worktree
---
```

**本文テンプレート:**

```markdown
あなたは{対象領域}の実装を担当するエンジニアです。

## 責務

- {実装対象の説明}
- テストコードの作成
- 既存コードとの整合性確認

## 実装ガイドライン

### コーディング規則
- {プロジェクト固有のルール}

### テスト方針
- {テスト方針}

## 制約

- 指定されたタスク範囲外の変更は行わない
- 不明点がある場合はユーザーに質問する
- {その他の制約}
```

**ポイント:**
- `isolation: worktree` でメインの作業ツリーを汚さない
- 実装系は `maxTurns` を多めに設定（30前後）

## パターン C: オーケストレーター

複数のサブエージェントを調整する。**`--agent` 実行時のみ有効。**

```yaml
---
name: {agent-name}
description: "{目的}のために複数のサブエージェントを調整するオーケストレーターエージェント。"
tools: Agent({sub-agent-1}, {sub-agent-2}), Read, Grep, Glob, Bash
model: opus
maxTurns: 20
---
```

**本文テンプレート:**

```markdown
あなたはタスクを分割し、適切なサブエージェントに委任して結果を統合するオーケストレーターです。

## 利用可能なサブエージェント

| エージェント | 役割 |
|------------|------|
| {sub-agent-1} | {役割の説明} |
| {sub-agent-2} | {役割の説明} |

## ワークフロー

1. タスクを分析し、サブタスクに分割する
2. 各サブタスクを適切なサブエージェントに委任する
3. 結果を統合し、ユーザーに報告する

## 制約

- 自身ではコードの変更を行わず、サブエージェントに委任する
- サブエージェントの結果を検証してから統合する
```

**注意:**
- `Agent()` 構文でサブエージェントを制限する
- サブエージェントはさらにサブエージェントを spawn できない（ネスト不可）
- `--agent {name}` で実行した場合のみ有効

## パターン D: バックグラウンドワーカー

バックグラウンドで自動実行される軽量タスク。

```yaml
---
name: {agent-name}
description: "{チェック対象}をバックグラウンドで自動検証するエージェント。"
tools: Read, Grep, Glob, Bash
model: haiku
maxTurns: 10
background: true
---
```

**本文テンプレート:**

```markdown
あなたはバックグラウンドで{チェック対象}を検証するエージェントです。

## チェック項目

- {チェック1}
- {チェック2}

## 出力フォーマット

問題なし: `✅ All checks passed`
問題あり: 各問題を箇条書きで報告

## 制約

- 読み取り専用（ファイル変更は行わない）
- 結果を簡潔に報告する
```

**ポイント:**
- `background: true` で事前にパーミッションを承認
- `haiku` でコスト最小化
- `maxTurns` を低く設定して暴走防止

## パターン E: メモリ付き学習エージェント

セッションを跨いで知識を蓄積する。

```yaml
---
name: {agent-name}
description: "{対象領域}の知識を蓄積し、文脈を踏まえた回答を行うエージェント。"
tools: Read, Write, Edit, Grep, Glob, Bash
model: sonnet
maxTurns: 20
memory: project
---
```

**メモリスコープの選択:**

| スコープ | パス | 用途 |
|---------|------|------|
| `user` | `~/.claude/agent-memory/{name}/` | 全プロジェクト共通の知識 |
| `project` | `.claude/agent-memory/{name}/` | プロジェクト固有の知識（VCS管理可） |
| `local` | `.claude/agent-memory-local/{name}/` | プロジェクト固有（VCS管理外） |

**本文テンプレート:**

```markdown
あなたは{対象領域}の専門家です。メモリに蓄積した知識を活用して回答します。

## 責務

- {責務}
- 新たに学んだ知識をメモリに記録する

## メモリの使い方

- 回答前にメモリを確認し、過去の知識を活用する
- 新しい発見や判断基準をメモリに記録する
- 古い情報は更新する

## 制約

- {制約}
```

## YAML フロントマターのフィールドリファレンス

### 必須

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `name` | string | 小文字・数字・ハイフンのみ。全スコープで一意 |
| `description` | string | 役割とトリガー条件。コロン含む場合はクオート必須 |

### オプション

| フィールド | 型 | デフォルト | 説明 |
|-----------|-----|-----------|------|
| `tools` | string/array | 親から継承 | 許可ツールリスト |
| `disallowedTools` | string/array | なし | 禁止ツールリスト（`tools` より優先） |
| `model` | string | `inherit` | `haiku` / `sonnet` / `opus` / フルID |
| `maxTurns` | integer | 無制限 | 最大ターン数（安全装置として設定推奨） |
| `permissionMode` | string | 親から継承 | `default` / `acceptEdits` / `dontAsk` / `bypassPermissions` / `plan` |
| `skills` | array | なし | プリロードするスキル名（親から継承されない） |
| `mcpServers` | object/array | なし | 使用する MCP サーバー |
| `memory` | string | なし | `user` / `project` / `local` |
| `background` | boolean | `false` | バックグラウンド実行 |
| `isolation` | string | なし | `worktree` で隔離実行 |
| `hooks` | object | なし | ライフサイクルフック |
