## 設計契約（orchestra Wave 0 互換・4項目）

### 1. エンティティ関係図

主要な型・構造体の関係と、ID がどう流れるかを示す。

```
{例: User(id) --1:N--> Order(id, user_id) --1:N--> OrderItem(id, order_id)}
{ID の流れ: リクエスト order_id → Order 取得 → 紐づく OrderItem を解決}
```

### 2. モジュール境界の API

モジュール間の呼び出しインターフェース。関数シグネチャと**戻り値の意味**を明記する。

| モジュール | 関数シグネチャ | 戻り値の意味 |
|---|---|---|
| {module-a} | `fn process(input: T) -> Result<U, E>` | {成功時 U / 失敗時 E の意味} |
| {module-b} | `fn fetch(id: Id) -> Option<Entity>` | {見つからなければ None} |

### 3. データフロー

イベントがどの順序でどのモジュールを通るかを示す。

```
{1. Controller が入力を受領}
   ↓
{2. UseCase がバリデーション → Repository へ}
   ↓
{3. Repository が永続化 → 結果を UseCase へ返却}
   ↓
{4. Controller がレスポンス整形}
```

### 4. 共有型の定義場所

どの型をどのモジュールに置くか。**重複定義の禁止ルール**を明記する。

| 共有型 | 定義場所 | 利用側 |
|---|---|---|
| {Entity} | {domain/entity.ts} | {usecase, repository} |
| {DTO} | {dto/index.ts} | {controller, usecase} |

> 重複定義禁止: 同じ型を複数モジュールで再定義しない。上記の定義場所を単一の真実のソースとする。

## タスク分解（Wave / 順序）

実装順序と並列可否を示す。orchestra に渡す場合はそのまま Wave 割りとして使える。

| Wave | タスク | 担当（impl-1/impl-2/tester 等） | 依存（先行 Wave） | 並列可否 |
|---|---|---|---|---|
| 0 | 設計契約（本書の流用） | leader | — | — |
| 1 | {型定義・基盤} | impl-1 | — | 可 |
| 1 | {API ルート} | impl-2 | — | 可 |
| 1 | {仕様ベーステスト作成} | tester | — | 可 |
| 2 | {応用実装} | impl-1/2 | Wave 1 | 可 |

> solo-with-verifier に渡す場合は Wave を使わず、1〜3個のタスクを直列の番号付きリストで列挙する。
